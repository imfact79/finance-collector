# 기간별 최적 비중 추천

## 사용자 결과

사용자가 시뮬레이션 기간을 고르면, 그 기간의 코스피와 국고채 10년물 과거 통계로 계산한 **수익률 기준 최적 비중**과 **MDD 기준 최적 비중**을 한 화면에서 나란히 본다. 두 결과 옆에는 "과거 데이터 기반이며 미래 수익을 보장하지 않는다"는 고지가 항상 함께 보인다.

비중을 느낌이 아니라 과거 통계로 정하게 한다는 [PRODUCT.md](../../../PRODUCT.md)의 약속 중, 핵심 루프의 1·2단계(기간 선택 → 두 기준의 추천 확인)를 처음으로 끝까지 동작시키는 작업이다.

## 범위

### 포함

- 시뮬레이션 기간 선택(시작 월, 종료 월)
- 수익률 기준 추천과 MDD 기준 추천의 계산과 나란한 표시
- 결과와 함께 보이는 한계 고지
- 계산에 쓰는 통계의 저장과 조회: ECOS에서 받은 월별 통계를 Supabase 테이블에 저장하고, 화면은 그 테이블을 읽는다.
- 통계가 없거나 읽기에 실패했을 때의 상태 표시

### 이번 작업에서 하지 않는 것

- 사용자가 직접 입력한 비중의 결과 확인 (핵심 루프 2단계의 나머지 절반, 다음 작업)
- 통계 갱신 흐름과 갱신 후 재계산 (핵심 루프 4단계, 다음 작업)
- 로그인, 사용자별 저장, 결과 공유
- 차트 등 시계열 시각화
- 거래 비용, 세금 반영 (제품 차원에서 반영하지 않기로 함)

## 사용자가 보는 흐름과 인수 기준

1. 첫 화면에 기간 선택이 있고, 기본값은 통계가 제공되는 전체 범위다. 선택 가능한 범위는 두 통계가 모두 있는 달로 제한된다. 범위 밖의 달은 고를 수 없다.
2. 사용자가 기간을 정하면(또는 기본 기간 그대로) 결과가 나온다. 결과는 두 묶음이다.
   - 수익률 기준 추천: 추천 주식 비중과 채권 비중, 그 비중의 연환산 수익률과 MDD
   - MDD 기준 추천: 추천 주식 비중과 채권 비중, 그 비중의 연환산 수익률과 MDD
3. 두 묶음은 같은 정보 구성으로 나란히 놓여 한눈에 비교된다. 좁은 화면에서는 위아래로 쌓이되 순서와 정보는 그대로다.
4. 기간을 바꾸면 결과가 새 기간 기준으로 바뀐다. 기간이 달라지면 추천 비중도 달라질 수 있다.
5. 한계 고지는 결과가 보이는 동안 항상 화면에 있다. 접거나 숨길 수 없다. 고지에는 아래 내용이 들어간다.
   - 과거 데이터 기반이며 미래 수익을 보장하지 않는다.
   - 거래 비용과 세금은 반영하지 않았다.
   - 국고채 수익률은 금리로부터 근사한 값이다.
   - 최종 결정은 사용자의 몫이다.
6. 너무 짧은 기간(12개월 미만)은 계산하지 않고, 이유를 알려 주며 기간을 다시 고르게 한다.
7. 통계 조회가 실패하거나 통계가 비어 있으면, 결과 자리에 오류 또는 빈 상태가 보이고 사용자가 다음에 할 일이 드러난다. 가짜 결과를 보여 주지 않는다.
8. 결과의 두 추천 비중은 모든 후보 비중(주식 0%부터 100%까지 1%p 간격)을 같은 방식으로 계산해 비교한 값과 일치한다. 즉 수익률 기준 추천은 후보 중 연환산 수익률이 가장 높은 비중이고, MDD 기준 추천은 MDD가 가장 작은(낙폭이 얕은) 비중이다. 같은 값이 여럿이면 다른 지표가 더 좋은 쪽을 고르고, 그래도 같으면 주식 비중이 낮은 쪽을 고른다.

## 계산 규약 (제품이 약속하는 계산 의미)

- 투자 대상은 코스피와 국고채 10년물, 리밸런싱은 분기 단위다.
- 통계의 시계열 단위는 **월말**이다. 코스피는 월말 종가, 국고채는 10년물 월별 금리다.
- 리밸런싱은 선택한 기간의 시작 월을 기준으로 3개월마다 목표 비중으로 되돌린다. 리밸런싱 사이에는 비중이 자산 수익에 따라 자연스럽게 흘러간다.
- MDD는 월말 평가액 기준으로, 기간 중 직전 최고점 대비 가장 큰 하락률이다.
- 수익률은 기간 전체를 연환산한 값이다.
- 국고채는 금리만 제공되므로 월 수익률을 근사한다. 전월 금리를 이자 수익(1/12)으로 보고, 금리 변화에 따른 가격 변동을 고정 듀레이션으로 더한다. 정확한 채권 총수익지수가 아니라 근사임을 화면에 알린다.
- 거래 비용, 세금은 계산에 넣지 않는다.

## 통계 출처

- 한국은행 ECOS Open API에서 받는다. 확인된 계열은 다음과 같다(2026-10-29 확인).
  - 국고채(10년) 월별 금리: 통계표 `721Y001`, 항목 `5050000`, 2000-10부터 2026-09까지 312개월
  - KOSPI 월말 종가: 통계표 `901Y014`, 항목 `1070000`, 2000-02부터 2026-09까지 320개월
- 두 계열이 모두 있는 2000-10부터 2026-09가 시뮬레이션 가능 범위다.
- 받은 통계는 Supabase 테이블에 저장하고, 화면의 계산은 그 테이블 값만 쓴다. ECOS API 키는 브라우저로 나가지 않는다.
- 선택 근거: 저장소 안에 고정하는 방안보다 갱신 흐름(다음 작업)과 바로 이어지고, 실시간 호출 방안보다 응답과 검증이 안정적이다.
- 통계를 처음 채우는 일은 이번 작업에 포함한다. 이후 갱신 흐름은 포함하지 않는다.

## 연결된 결정과 맥락

- [PRODUCT.md](../../../PRODUCT.md): 서비스 전제. 이 작업은 핵심 루프 1·2단계, 두 기준의 나란한 비교, 결과 한계의 명시, 최종 결정은 사용자 몫이라는 원칙을 따른다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md): 화면 구성 원칙. 기간 선택, 결과, 고지, 빈 상태와 오류 상태는 이 계약의 공통 composition과 상태 설계 규칙을 따른다.
- Supabase 작업은 `AGENTS.md`의 Supabase 지침과 설치된 `supabase`, `supabase-postgres-best-practices` 스킬을 따른다.
- 프로토타입은 만들지 않았다. 입력 하나와 결과 두 묶음인 단일 화면이라 구현 후 실제 화면으로 판단하는 편이 싸다.

## 가정 (에이전트가 정했고 바꿀 수 있음)

- 후보 비중은 1%p 간격이다.
- 최소 기간은 12개월이다.
- 기간 단위는 월이고, 리밸런싱 시점은 선택한 시작 월을 기준으로 3개월 간격이다.
- 표시하는 수익률은 연환산 수익률이다. 누적 수익률은 이번에 보여 주지 않는다. 추천 순위는 둘이 같다.
- 채권 월 수익률 근사에 쓰는 듀레이션은 하나의 고정값이다. 값 자체는 구현에서 근거와 함께 정한다.
- 이 화면은 로그인 없이 누구나 연다. 통계 테이블은 읽기만 공개한다.
- 코스피 월말 종가는 가격 지수이므로 배당은 반영되지 않는다. 고지에 한 줄 포함한다.

## 범위 밖 영역과 이유

- `app/page.tsx`의 기존 템플릿 화면은 이 화면으로 대체되므로 관련 테스트(`app/page.test.tsx`, `e2e/smoke.spec.ts`)도 새 화면에 맞게 바뀐다. 그 외 템플릿 설정(Vitest, Playwright 구성)은 건드리지 않는다.
- 사용자 계정과 개인화는 제품 정의에 아직 없으므로 건드리지 않는다.

## 미룬 결정

- 직접 입력한 비중의 결과 표시: 다음 작업에서 정한다. 이번 화면은 입력창을 두지 않는다.
- 통계 갱신 방식(수동 재실행, 예약 실행 등)과 갱신 후 안내: 다음 작업에서 정한다. 그때까지 통계는 처음 채운 시점에 멈춰 있고, 화면은 마지막 통계 월을 보여 주어 최신성을 알 수 있게 한다.
- 채권 수익률을 총수익지수 기반으로 바꿀지 여부: 쓸 수 있는 공식 총수익지수가 확인되면 다시 판단한다.

## 남은 위험

- **쓰기 권한**: 환경에 있는 Supabase 키는 공개용(publishable)이라 통계 테이블에 값을 넣으려면 별도 방법이 필요하다. 구현 단계에서 테이블 생성과 초기 적재 방식을 정하되, 서비스 키가 필요하면 사용자에게 요청한다.
- **채권 근사 오차**: 금리 기반 근사라서 실제 국고채 지수와 수치가 다르다. 추천 비중의 순서에는 영향이 작지만 절대 수치는 다를 수 있다. 고지로 완화한다.
- **MDD 기준 추천의 쏠림**: MDD가 가장 작은 비중은 채권 쪽으로 크게 치우칠 가능성이 높다. 결과가 이상하게 보여도 규약대로의 값이며, 수익률과 MDD를 함께 보여 주는 이유이기도 하다.
- **월 단위 MDD**: 월말 값만 쓰므로 월 중간의 하락은 반영되지 않아 실제보다 작게 나온다. 고지에 포함하는 것을 검토한다.
- **ECOS 응답 변동**: 통계표 코드나 항목이 바뀌면 적재가 실패할 수 있다.
